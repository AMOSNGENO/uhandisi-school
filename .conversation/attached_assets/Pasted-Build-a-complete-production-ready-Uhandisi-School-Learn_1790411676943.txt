Build a complete, production-ready **Uhandisi School Learning Management System (LMS)** as a standalone web application. Do NOT use Moodle or depend on Moodle in any way.

The system should be designed specifically around **Lipa Pole Pole (pay-as-you-go/installment learning)** where students can pay small amounts through M-Pesa and progressively unlock course modules according to the amount they have paid.

## 1. Project Identity

Name: **Uhandisi School**

Website: **uhandisischool.com**

Tagline:

**“Learn for as Little as KSh100 a Day”**

The platform should be modern, responsive, fast, mobile-first, professional, and optimized for Kenyan students.

# 6. IMPORTANT PAYMENT RULE

Never trust the amount sent by the frontend.

The backend must determine:

* Student
* Course
* Amount
* M-Pesa transaction
* Transaction status
* Cumulative amount paid
* Remaining balance
* Modules unlocked

Only successful/confirmed M-Pesa transactions count toward access.

Pending, cancelled, failed or duplicate transactions must NOT unlock content.

Implement:

Phone number
Amount

Example:

Amount:
KSh 200

Phone:
07XXXXXXXX

Student clicks:

Backend:

1. Generate/access M-Pesa access token
2. Send STK Push
3. Save transaction as pending
4. Wait for callback
5. Process callback
6. Mark payment completed/failed
7. Recalculate student's course balance
8. Unlock eligible modules
9. Update dashboard

Show clear statuses:

“Payment request sent to your phone.”

“Waiting for M-Pesa confirmation…”

“Payment successful.”

“Payment failed. Please try again.”

# 9. M-PESA CALLBACK

Example:

* Validate request
* Identify transaction
* Extract M-Pesa receipt
* Extract amount
* Extract phone number
* Extract transaction date
* Store transaction
* Prevent duplicates
* Mark payment completed
* Recalculate course balance
* Update module access

# 35. MOST IMPORTANT REQUIREMENT

The application must be designed around **module-based progressive access**, not traditional one-time course enrollment.

A student does not necessarily need to pay the entire course price before learning.

The student's cumulative successful payments determine which modules are accessible.

The system must always know:

How much the student has paid

How much remains

Which modules are unlocked

Which module is next

How much more the student needs to pay

This information must be calculated server-side and reflected consistently throughout the application.

Build the system as a real production application, not a demo or static prototype.
